# AgentShield — Testing & Security Validation

## 1. Automated tests

Always run backend tests against a throwaway database (the `.env` file may point at production):

```powershell
cd backend
$env:DATABASE_URL = "sqlite:///./test_agentshield.db"
Remove-Item .\test_agentshield.db -ErrorAction SilentlyContinue   # start from a fresh file (see note below)
.venv\Scripts\python.exe -m pytest tests -q

cd ..\extension
npm test            # detector parity + policy + website decisions + activation and licence state machine (no browser needed)
npx tsc --noEmit    # type check
node build.js

cd ..\dashboard
npm run build       # type check + production build

cd ..\admin-console
npm install; npm run build   # internal console: type check + production build
```

The backend tests need **no credentials in code or in `.env`**: `backend/tests/conftest.py` sets throwaway, test-only environment values (signing key, a test company admin, the demo auditor password, reminder loop off) with `setdefault` before the app is imported. Since 2.0.0 the tests use these test-only passwords, not the passwords published by older releases. They exist only for the test run; never reuse them on a real server.

## 2. Manual end-to-end scenarios

Use synthetic data only. With `DEMO_MODE=true` the dashboard's **Guided Demo** page runs these and verifies each one against real events.

### Activation end-to-end (run first)

1. Start the backend on a SQLite test database **without** SMTP: `$env:DATABASE_URL = "sqlite:///./test_agentshield.db"`, then start uvicorn and the dashboard (`npm run dev`) as in DEPLOYMENT.md §3.
2. Sign in as the initial admin (create it by setting throwaway `INITIAL_ADMIN_EMAIL` and `INITIAL_ADMIN_PASSWORD` values before the first start of the test database; its company then has an internal licence. There are no built-in logins) → **Users & Devices** → **Invite someone** with a test email (role EMPLOYEE). (Or test self sign-up and the trial instead: scenarios 23–24.)
3. Copy the invite link from the backend console, open it, and set a password (12+ characters).
4. Sign in as that account → **My activation** → **Generate activation code**.
5. Load the unpacked extension (`extension/` after `node build.js`). Open chatgpt.com: the **Activation Required** page appears.
6. Click the AgentShield icon (**AgentShieldAI — Activation Required**, three numbered steps) → paste the code in **Activation code** → **Connect and verify**. No email or password is asked. The popup shows success only after the server confirms, signed in as the account that generated the code.
7. Open chatgpt.com again: the page loads and prompts are checked (scenario 2 is blocked).
8. As admin, **Users & Devices** → Authorized browsers → **Revoke** that browser. At its next request to the server (at the latest its next 5-minute sync, immediately after **Sync policies**), AI sites show **Activation Required** again.

## 4. Known gaps

See [SECURITY_ARCHITECTURE.md §5](./SECURITY_ARCHITECTURE.md#5-limitations-not-enforced). In particular: no browser-automation (Playwright) tests for the extension yet; PDF/Office content not inspected; Firefox/Safari unsupported; identity not SSO-verified. For 2.1.0: metering counts only what activated extensions report (a modified extension could under-report; protection still stops server-side when access ends); the offline queue holds at most 500 events; the usage month is the UTC calendar month; credits never expire, no proration, receipts only; company features are hidden and refused for individual accounts; credit packs are tested only against a fake Razorpay. For 2.0.0 (internal console, Phase A): staff lockout and rate limits are per-process memory; staff MFA is TOTP only (no hardware key / WebAuthn); the staff session token is kept in `sessionStorage`, so an XSS in the console would expose it (the console loads no third-party scripts, only Google Fonts); analytics, support and operations pages (Phases B–D) are not built yet; INTERNAL licences still exist for the initial company. For 1.5.1: sign-up does not confirm the email, so someone can register an address they do not own and use up that domain's one trial (the real owner recovers the account with **Forgot password?**), and a 409 on sign-up reveals that an account exists (limited by the sign-up rate limit). For 1.5.0: payments are tested only against a fake Razorpay so far (scenarios 32–37 in Razorpay test mode are still to do); receipts are not GST tax invoices; no proration when switching plans; Reconcile covers one-time orders only (monthly charges rely on webhooks). For 1.4.0: trial-abuse controls raise the cost of repeated trials but someone with new emails, domains and networks can still claim more; licence expiry, revocation and suspension reach a browser at its next server request (sessions at most 15 minutes, sync every 5 minutes); in-memory rate limits are per process.
